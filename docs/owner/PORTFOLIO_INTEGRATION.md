## Data exchange boundaries

Schema 1 planning inputs/results and schema 2 continuity scenarios/runs have distinct shapes. Continuity output uses decimal text, elapsed seconds, kW/kWh and positive source delivery with signed stored-energy change. EMT output uses floating SI quantities and signed source current/energy. Dynamics output uses normalized states, solver diagnostics and study-specific units. Infrastructure screens carry units, evidence metadata and explicit noncertification/HOLD semantics. An aggregator must preserve these labels rather than align fields by similar names alone. [Interface contracts](../developer/API_CLI_AND_INTERFACES.md), [symbol glossary](../math-and-physics/PARAMETERS_AND_SYMBOLS.md).

The existing data exports and citations are confirmed integration surfaces. No runtime import, shared database, orchestrated control loop, common calibration dataset or cross-repository execution dependency is established by this documentation review. Reuse should begin with an explicit adapter contract, unit/sign mapping, provenance and a small reproducible fixture, not an assumed integration.

## Status exchange

Publish content readiness, independent QA, remote checks, merge and deployment as separate dated fields. Source tests do not become candidate tests by renaming the revision. A historical badge or reachable home page is not evidence that a new handbook is deployed. Keep the final commit/deployment receipts outside the self-referential document they identify, or add an accurately dated later update.

## Suggested shared work

Generic lessons from this package include accountable tree/interface dispositions, explicit scientific units, deterministic evidence identities and independent candidate review. A portfolio coordinator may deduplicate those methods while retaining repository-specific equations, claims and execution limits. The roadmap contains no asserted dependency on another repository; suggested shared review tooling is organizational reuse, not an installed software integration.
