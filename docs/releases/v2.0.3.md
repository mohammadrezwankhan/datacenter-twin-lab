# 2.0.3 — Maintained dependencies and bounded input errors

This maintenance version updates compatible API, browser, build, quality and security dependencies and corrects an EMT input-validation edge case. Publication and deployment are separate steps; the source change does not itself establish that a package or hosted site has been published.

## Behavior and compatibility

An oversized integer or signaling Decimal NaN in any bounded EMT field now raises the documented `InputError`. The command-line entry point reports the invalid field, returns exit status 2 and creates no output file. The regression covers positive and negative 401-digit integers across all ten input fields and the actual command-line path.

Python, JavaScript, dashboard package and citation metadata use version 2.0.3. Planning schema 1, electrical schema 2, the existing study equations, supported operating systems and Python versions, browser/native parity tolerances and deployment guards remain unchanged.

Dependency updates use complete regenerated locks. The legacy `.lock` entry points include the maintained `.txt` locks. Root lint tooling retains TypeScript 6.0.3 because the current TypeScript-ESLint peer contract excludes TypeScript 6.1 and later; the application continues to use TypeScript 7.0.2. Reviewed custom scanner contracts require separate source and parser qualification before replacing their pinned versions. See [dependency validation](../engineering/dependency-validation.md) and [security tooling](../../.github/security/README.md).
